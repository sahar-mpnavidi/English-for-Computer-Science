### 3. Reading / متن اصلی

**عنوان متن: The Languages of Machines (زبان‌های ماشین‌ها)**

**[1]** Programming is the work of telling a computer what to do. You write source code in a programming language such as Python, Java, or C, and the computer follows your instructions. A program is only a text file until somebody executes it. Learning a language is learning a way of thinking.

**[2]** Languages are not all the same. A high-level language is close to human language, and it is easier to read. A low-level language is closer to the machine, and it gives you more control. Machine code is the lowest level: a long list of numbers that only the processor understands. Assembly is a low-level language with short names for those numbers.

**[3]** How does the machine understand your text? A compiler translates the whole program at once into machine code or bytecode before it runs. An interpreter translates and executes the program line by line while it runs. A compiler usually gives you a faster program, but an interpreter gives you faster feedback.

**[4]** Every language has its own syntax and semantics. Syntax is the form of the language: the correct order of words and signs. Semantics is the meaning: what the program really does. A missing bracket is a syntax error, but a program that counts the wrong number has a semantic problem. Both can stop your work.

**[5]** Before you use a value, you must declare it and give it a data type. A declaration tells the computer the name and the type. Then you assign a value to that name. In some languages you also define a constant: a value that never changes. A strict language checks every type, and this prevents many errors.

**[6]** How does a program make a decision? With a condition and a statement. An operator such as == or > compares two values, and an if-statement chooses one way. A loop repeats a piece of code; to iterate means to repeat it again and again. Every program is a combination of these small pieces.

**[7]** A procedure is a block of code with a name. You invoke it when you need it, so you do not write the same lines again. A parameter is the name in the definition, and an argument is the real value that you send. The procedure can return a result. A good procedure does one job.

**[8]** Modern languages are object-oriented. An object has data and procedures together, and a framework gives you ready pieces for a large program. With inheritance, a new object can inherit the behaviour of another one; with override, it can change one part. This is called an object-oriented design.

**[9]** You do not write everything yourself. A module is a group of procedures with one job, and you import it when you need it. You can export your own module for other people. A big program uses many modules, and this modular design is one of the secrets of maintainable code.

**[10]** An algorithm is a clear list of steps for solving a problem. Programmers often write an algorithm in pseudocode first: a language that looks like code but is for people, not for a machine. Then they convert it into a real language. A good algorithm is correct, and a great one is also efficient.

**[11]** Nothing works perfectly the first time. A bug is a mistake in the code, and debugging is the work of finding it. An error stops the program, and an exception is a special event that the program can handle. A trace shows the steps that led to the problem. To debug well, read the message carefully.

**[12]** Good programmers test their code. A testable program is easier to check, and a small unit test can save hours. You can simulate a real situation and see what happens. Then you tune the code: you make small changes to optimize the speed. Sometimes the difference between a slow program and a fast one is one line.

**[13]** Some programs must do many things at the same time. A concurrent program works on two jobs together, and an asynchronous program does not wait for a slow job to finish. Synchronous code is simpler to read, but asynchronous code is better for networks. Every choice has a price.

**[14]** What makes code good? Good code is readable and concise: a reader understands it quickly. It is consistent, so every module looks the same. It is elegant, with no useless lines, and it is robust: it still works when the input is strange. Verbose code, on the other hand, uses three lines for one idea.

**[15]** Old code must change, and change is dangerous. To refactor means to improve the structure without changing the behaviour. A reusable function saves time in the next project. If you find deprecated code, replace it, because the newest version of the language does not support it any more.

**[16]** Some problems are complex, and the answer is not a straight line. A nested loop sits inside another loop. A recursive procedure calls itself, and it is elegant for some problems and dangerous for others. A functional language uses small functions, and a declarative language describes the result instead of the steps. A procedural language is the older style: it works step by step, from the first line to the last.

**[17]** Languages also differ in their type systems. A static language checks the types before the program runs, and a dynamic language checks them while it runs. A strict system catches more errors early. A lightweight language is easy to learn, and a versatile language can work on a website, a phone, and a server.

**[18]** Nobody writes alone in a modern team. Version control keeps every change, and a commit is one saved change with a message. A branch lets you work on a new idea, and a merge brings the branch back. If something breaks, a revert takes you back. A build creates the program that you will release.

**[19]** Some languages are open-source, so everybody can read and change them; others are proprietary. A mature language has many modules and years of documentation, and a new one can be more exciting but less stable. Before you choose, specify your real needs: a website, a game, or a data program.

**[20]** Mina wrote her first program last month. She declared a string value, assigned her name to it, and invoked a small procedure. The compiler found one error: she had forgotten a bracket. She implemented the whole algorithm in twenty lines. The message was not clear, so she traced the line and parsed the text again. Ten minutes later, the program printed her name.

**[21]** Which language is better? It depends on the job. Python is easier than C, and its syntax is shorter, but C is faster and gives more control. JavaScript is more popular than many other languages for websites, and Java is older than Python. There is no perfect language.

**[22]** Which language is the most used in the world? Different lists give different answers, but the biggest lists usually put Python, JavaScript, and Java at the top. Python is often the easiest language for a beginner, and C is one of the fastest. The most important question is not the list. The best language is the one that solves your problem.

**[23]** How does a team work on one program? One person writes a module and a second person reviews it. They commit, merge, and build the program together, and then they release a new version. When two people change the same line, they must agree on the answer. This daily conversation is called code review.

**[24]** Is programming a good career? It is one of the most flexible jobs in the world: a developer can work in an office, at home, or in another country. The salary is usually higher than the average salary, and the market is bigger than it was ten years ago. Programming is also one of the most creative technical jobs.

**[25]** What should you learn next? A beginner should learn one language first and write small programs every day. It is better to know one language deeply than five languages badly. Read other people's code, because it is one of the fastest ways to improve. Remember: the most readable code is the easiest to change.

**[26]** What will change in the next ten years? Many programmers believe that artificial intelligence will write more code, and that developers will spend more time on design and on reading code than on typing. The most valuable skill will be the ability to explain a problem clearly. Syntax will be less important than thinking.

**[27]** Programming is a language, a craft, and a habit. A language has syntax and semantics; a craft needs practice, testing, and refactoring; a habit means writing a little every day. The best programmers are not the ones who write the most lines; they are the ones who delete the most lines. That is the shortest description of good code.

**[28]** Documentation is the quiet part of programming. You document a module once, and fifty people use it for years without asking you. A comment explains one line, and a good name explains the code by itself. The most expensive program is the one that nobody can understand after six months.

**[29]** Nothing of this is a secret. A language is a tool, and the same ideas appear in every tool: values and types, conditions and loops, procedures and objects, tests and refactoring. If you learn these ideas in one language, the second language is easier than the first. The hardest step is the first step.

**[۱]** برنامه‌نویسی کارِ گفتن آنچه کامپیوتر باید انجام دهد است. شما کد منبع را در یک زبان برنامه‌نویسی مانند پایتون، جاوا یا C می‌نویسید و کامپیوتر دستورهای شما را پیروی می‌کند. یک برنامه فقط یک فایل متنی است تا زمانی که کسی آن را اجرا کند. یاد گرفتن یک زبان، یاد گرفتن یک شیوهٔ فکر کردن است.

**[۳]** ماشین چگونه متن شما را می‌فهمد؟ یک کامپایلر کل برنامه را یک‌جا و پیش از اجرا به کد ماشین یا بایت‌کد ترجمه می‌کند. یک مفسر برنامه را خط‌به‌خط، همان‌طور که اجرا می‌شود، ترجمه و اجرا می‌کند. کامپایلر معمولاً برنامهٔ سریع‌تری می‌دهد، اما مفسر بازخورد سریع‌تری می‌دهد.

**[۴]** هر زبان نحو و معنای خودش را دارد. نحو شکلِ زبان است: ترتیب درست واژه‌ها و نشانه‌ها. معنا همان چیزی است که برنامه واقعاً انجام می‌دهد. یک پرانتز جاافتاده، خطای نحوی است؛ اما برنامه‌ای که شمار اشتباهی می‌شمارد، مشکل معنایی دارد.

**[۱۰]** الگوریتم فهرستی روشن از گام‌های حل یک مسئله است. برنامه‌نویس‌ها اغلب اول الگوریتم را در شبه‌کد می‌نویسند: زبانی که شبیه کد است اما برای انسان، نه برای ماشین. بعد آن را به یک زبان واقعی تبدیل می‌کنند. الگوریتم خوب درست است و الگوریتم عالی کارآمد هم هست.

**[۱۴]** چه چیزی کد را خوب می‌کند؟ کد خوب خوانا و مختصر است: خواننده آن را سریع می‌فهمد. یکدست است، پس همهٔ ماژول‌ها یک‌شکل به نظر می‌رسند. شیک است، بدون خط‌های بی‌استفاده، و مقاوم است: با ورودی عجیب هم کار می‌کند. در برابر آن، کد پرگو برای یک ایده سه خط مصرف می‌کند.

**[۱۸]** در یک تیم امروزی هیچ‌کس تنها نمی‌نویسد. کنترل نسخه هر تغییر را نگه می‌دارد و هر «ثبت» یک تغییر ذخیره‌شده با یک پیام است. یک شاخه به شما اجازه می‌دهد روی ایدهٔ تازه کار کنید و ادغام، شاخه را برمی‌گرداند. اگر چیزی خراب شود، بازگرداندن شما را به عقب می‌برد. یک ساخت، برنامه‌ای را می‌سازد که آن را منتشر خواهید کرد.

**[۲۵]** بعد چه چیزی را باید یاد بگیرید؟ یک مبتدی باید اول یک زبان را یاد بگیرد و هر روز برنامه‌های کوچک بنویسد. بهتر است یک زبان را عمیق بدانید تا پنج زبان را بد. کد دیگران را بخوانید، چون یکی از سریع‌ترین راه‌های پیشرفت است. یادتان باشد: خواناترین کد، آسان‌ترین کد برای تغییر است.

**خلاصهٔ فارسی متن:**

این درس نشان می‌دهد کد چیست و چگونه از متن انسان به حرکت ماشین تبدیل می‌شود. زبان‌های سطح بالا به زبان انسان نزدیک‌اند و زبان‌های سطح پایین به ماشین؛ کد ماشین پایین‌ترین سطح است و اسمبلی، سطح پایین با نام‌های کوتاه. کامپایلر کل برنامه را یک‌جا به کد ماشین یا بایت‌کد ترجمه می‌کند و مفسر خط‌به‌خط ترجمه و اجرا می‌کند. هر زبان نحو (شکل) و معنا دارد و خطاها یا نحوی‌اند یا معنایی.

ساختار برنامه از اجزای کوچک ساخته می‌شود: نوع داده، اعلان، نسبت دادن مقدار، عملگر، دستور شرطی، حلقه، رویه با پارامتر و آرگومان، و بازگرداندن نتیجه. زبان‌های امروزی شیءگرا هستند و با ارث‌بری و بازنویسی کار می‌کنند؛ ماژول‌ها را می‌توان وارد و صادر کرد. برنامه‌نویس‌ها اول الگوریتم را در شبه‌کد می‌نویسند و بعد آن را پیاده‌سازی می‌کنند.

نگه‌داشتن کیفیت کد، کار روزانهٔ برنامه‌نویس است: آزمون‌پذیری، آزمایش واحد، شبیه‌سازی، تنظیم دقیق برای بهینه‌سازی، بازآرایی برای تغییر ساختار بدون تغییر رفتار، و پرهیز از کد منسوخ. کد خوب خوانا، مختصر، یکدست، شیک، مقاوم و قابل استفادهٔ مجدد است و از پیچیدگی‌هایی مانند حلقهٔ تودرتو و رویهٔ بازگشتی با احتیاط استفاده می‌کند. انواع زبان‌ها (ایستا در برابر پویا، سخت‌گیرانه در برابر سبک، بازمنبع در برابر انحصاری، رویه‌ای، کارکردی، اعلامی و شیءگرا) برای کارهای مختلف مناسب‌اند و کنترل نسخه (شاخه، ثبت، ادغام، بازگرداندن، ساخت و انتشار) کار تیمی را ممکن می‌کند.

### 7. Grammar Focus / نکتهٔ گرامری

**موضوع: صفت‌های مقایسه‌ای و عالی (comparatives and superlatives)**

**توضیح فارسی:**

برای مقایسهٔ دو چیز از **صفت مقایسه‌ای** و برای مقایسهٔ یک چیز با همهٔ گروه از **صفت عالی** استفاده می‌کنیم. صفت‌های **کوتاه** (یک‌سیلابی) با *-er* و *the -est* ساخته می‌شوند: *fast → faster → the fastest*. اگر صفت به «صامت + واکه + صامت» ختم شود، صامت آخر دو برابر می‌شود (*big → bigger → the biggest*)، و اگر به *y* ختم شود، *y* به *-ier / -iest* تبدیل می‌شود (*easy → easier → the easiest*). صفت‌های **بلند** (دو سیلابی و بیشتر) *more* و *the most* می‌گیرند: *readable → more readable → the most readable*.

**صفت‌های بی‌قاعده** را باید حفظ کرد: *good → better → the best*، *bad → worse → the worst*، *far → further → the furthest*، *little → less → the least*، *many / much → more → the most*.

**ساختارها:** در مقایسه از *than* استفاده می‌کنیم (*Python is easier than C.*) و در عالی از *the* با *in* یا *of* (*the most popular language in the world*, *the best of the three*). برای نشان دادن **برابری** از *as + صفت + as* استفاده می‌کنیم (*JavaScript is not as fast as C.*) و برای کمتر بودن از *less + صفت + than* (*Syntax is less important than thinking.*).

دو خطای رایج فارسی‌زبانان: ① جمع کردن دو نشانهٔ مقایسه («more easier» ← ~~more easier~~ / *easier*؛ «the most fastest» ← ~~the most fastest~~ / *the fastest*)؛ ② فراموش کردن دو برابر کردن صامت یا تبدیل *y* («more big» ← ~~more big~~ / *bigger*؛ «easyer» ← ~~easyer~~ / *easier*).

**جدول ۱ — ساخت صفت مقایسه‌ای و عالی:**

| نوع صفت | مقایسه‌ای | عالی | نمونه |
|---|---|---|---|
| کوتاه: + er / est | faster | the fastest | C is faster than Python. |
| پایان «صامت + واکه + صامت» | bigger | the biggest | This lock is bigger than that one. |
| پایان y | easier | the easiest | Python is easier than C. |
| بلند: more / most | more readable | the most readable | Good code is more readable. |
| بی‌قاعده | better / worse | the best / the worst | This is the best language for the job. |

**جدول ۲ — ساختارهای مقایسه:**

| ساختار | معنی | نمونه |
|---|---|---|
| صفت مقایسه‌ای + than | از … تر | C is faster than Python. |
| the + صفت عالی + in / of | …ترین | the most popular language in the world |
| as + صفت + as | به‌اندازهٔ … | JavaScript is not as fast as C. |
| less + صفت + than | کمتر از … | Syntax is less important than thinking. |

**جدول ۳ — صفت‌های بی‌قاعده و خطاهای رایج:**

| صفت | مقایسه‌ای | عالی |
|---|---|---|
| good | better | the best |
| bad | worse | the worst |
| far | further | the furthest |
| little | less | the least |
| many / much | more | the most |

- هر زبان برای چه کاری بهتر است؟
- دو شباهت و سه تفاوت مهم (سرعت، سادگی نحو، نوع داده، جامعهٔ کاربران، کاربرد).
- کدام زبان برای یک مبتدی مناسب‌تر است و چرا؟
- اگر بخواهید یکی را یاد بگیرید، کدام را انتخاب می‌کنید و چرا؟

**شرایط نگارش:**

- نوشته بین **۱۲۰ تا ۲۰۰ واژه** باشد.
- دست‌کم **۶ جملهٔ مقایسه‌ای** با *-er / more … than* بنویسید.
- دست‌کم **۳ جملهٔ عالی** با *the -est / the most* داشته باشد.
- دست‌کم یک بار **as … as** و یک بار **less … than** به کار ببرید.
- دست‌کم **۱۰ واژه** از جدول‌های واژگان بخش ۲ استفاده شود.

### 10. Mini Project / پروژهٔ کوچک

**انشا (نیمه‌تحقیقی): گزارش یک زبان برنامه‌نویسی**

یک زبان برنامه‌نویسی انتخاب کنید (پایتون، جاوااسکریپت، C، جاوا، یا هر زبان دیگری) و دربارهٔ آن گزارش کوتاهی بنویسید:

- **شناسنامه:** نام زبان، سال نخستین انتشار، سازنده، و نوع آن (سطح بالا یا پایین، ایستا یا پویا، بازمنبع یا انحصاری، شیءگرا، رویه‌ای، کارکردی یا اعلامی).
- **کاربرد:** آن زبان بیشتر برای چه کارهایی استفاده می‌شود؟ سه کاربرد واقعی بنویسید.
- **نمونهٔ کد:** یک نمونهٔ کوچک **دست‌نویس** (۵ تا ۸ خط) از آن زبان بنویسید و در آن دست‌کم یک متغیر، یک شرط یا حلقه، و یک توضیح (comment) داشته باشید.
- **جدول مقایسه:** یک **جدول دستی** با چهار سطر بکشید و این زبان را با زبان دیگری در چهار مورد مقایسه کنید: سادگی یادگیری، سرعت اجرا، تعداد ماژول‌ها و کتابخانه‌ها، کاربرد صنعتی.
- **مقایسه در جمله:** سه جملهٔ مقایسه‌ای و یک جملهٔ عالی دربارهٔ این دو زبان بنویسید.
- **برنامهٔ یادگیری:** در دو ماه آینده چه چیزی را یاد می‌گیرید (*going to*) و چه پیش‌بینی‌ای دربارهٔ آیندهٔ این زبان دارید (*will*)؟

**شرایط نگارش:**

- گزارش را **دست‌نویس روی کاغذ** بنویسید و در **جلسهٔ بعد** به مدرس تحویل دهید.
- دست‌کم **۲۰۰ واژه** باشد (بدون احتساب نمونهٔ کد و جدول).
- دست‌کم **۵ جملهٔ مقایسه‌ای**، **۳ جملهٔ عالی**، **۲ جملهٔ *going to*** و **۲ جملهٔ *will*** داشته باشد.
- دست‌کم **۱۲ واژه** از جدول‌های واژگان بخش ۲ در گزارش باشد.

**واژه‌های یاری‌دهنده:** syntax · semantics · compiler · interpreter · data type · algorithm · module · framework · readable · concise · maintainable · deprecated

### 11. Did You Know? / آیا می‌دانستید؟

1. **Python was first released in 1991, and it has been one of the most used languages in industry reports of 2023.**
   نخستین نسخهٔ پایتون در سال ۱۹۹۱ منتشر شد و در گزارش‌های صنعتی سال ۲۰۲۳ یکی از پرمصرف‌ترین زبان‌ها بوده است.

2. **The first high-level language, FORTRAN, appeared in 1957 for scientific calculations.**
   نخستین زبان سطح بالا، فورترن، در سال ۱۹۵۷ برای محاسبات علمی پدید آمد.

3. **The word "bug" for a computer problem became popular in 1947, after a moth was found inside a machine.**
   واژهٔ «bug» برای مشکل کامپیوتری در سال ۱۹۴۷ رایج شد، پس از آنکه بیدِ کوچکی درون یک ماشین پیدا شد.

4. **The first version of C appeared in 1972, and many modern languages still use its syntax.**
   نخستین نسخهٔ زبان C در سال ۱۹۷۲ پدید آمد و بسیاری از زبان‌های امروزی هنوز از نحو آن استفاده می‌کنند.

5. **Industry reports in 2023 showed that JavaScript and Python are used by more developers than any other language.**
   گزارش‌های صنعتی در سال ۲۰۲۳ نشان داد که جاوااسکریپت و پایتون بیش از هر زبان دیگری میان توسعه‌دهندگان به کار می‌روند.

6. **Some 2023 estimates counted more than 700 programming languages in real use, out of thousands that exist.**
   برخی برآوردهای ۲۰۲۳ بیش از ۷۰۰ زبان برنامه‌نویسی در استفادهٔ واقعی را شمردند، از میان هزاران زبانی که وجود دارد.

7. **A survey in 2023 found that most professional developers use more than one language in their daily work.**
   بررسی‌ای در سال ۲۰۲۳ نشان داد بیشتر توسعه‌دهندگان حرفه‌ای در کار روزانهٔ خود از بیش از یک زبان استفاده می‌کنند.

8. **The name "Python" does not come from the snake: it comes from a comedy group that the creator liked.**
   نام «پایتون» از مار نمی‌آید: از نام یک گروه کمدی می‌آید که سازندهٔ زبان دوستش داشت.
